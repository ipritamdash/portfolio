    Maya — Real-Time Voice AI (Orpheus 3B Pipeline)

    Stack: Orpheus 3B TTS · Llama 3.2 3B · faster-whisper large-v3-turbo · SNAC 24 kHz · llama.cpp · Pedalboard Hardware: 3× NVIDIA A10G (multi-GPU pipeline) Status: Production-Ready · Self-Hosted

    GitHub → HuggingFace (Orpheus GRPO LoRA) →

    Overview

    Maya is a fully local, real-time conversational voice AI. No external API calls, no cloud TTS — every component runs on the host GPUs. The pipeline achieves sub-800 ms time-to-first-audio by streaming sentences from the LLM into the TTS while the rest of the response is still being generated, and produces UTMOS 4.345 audio quality through a Pedalboard-based stateful post-processing chain.

    Pipeline

    graph LR
    A[User Audio<br/>WebSocket 24kHz] --> B[Silero VAD<br/>CPU · ~5ms]
    B --> C[faster-whisper<br/>large-v3-turbo · GPU 0]
    C --> D[Llama 3.2 3B<br/>llama.cpp Q4_K_M · GPU 1]
    D --> E[Orpheus 3B + SNAC<br/>llama.cpp Q4_K_M · GPU 2]
    E --> F[Pedalboard<br/>HPF → De-ess → Comp → EQ → Limiter]
    F --> G[WebSocket Out<br/>24kHz float32]

    Q4_K_M matches Q8_0 quality (Δ +0.002 UTMOS) while running 28 % faster — a clean Pareto win for production.

    Chain UTMOS Notes

    Streaming (stateful) 4.158 Per-chunk, state preserved across chunks via reset=False
    Streaming (stateless) 4.132 Old HPF + limiter baseline

    Custom Orpheus Fine-Tune (GRPO)

    Released as Tachyeon/orpheus-3b-conversational-grpo.
    Method GRPO (Group Relative Policy Optimization) — RL with UTMOS naturalness as the reward signal
    Base model canopylabs/orpheus-3b-0.1-ft (Llama 3.2 3B Instruct family, 3 B params)
    Adapter LoRA r=16, alpha=32, all linear layers
    Dataset Expresso (ylacombe/expresso)
    Hardware NVIDIA A10G 24 GB
    License Apache-2.0

    The reward signal directly targets perceived speech quality, side-stepping proxy losses that don't correlate well with human judgement of naturalness.

    Key Engineering Details

    Sentence-level streaming overlap

    The LLM streams its response sentence-by-sentence via SSE. TTS begins generating audio for sentence 1 while the LLM is still producing sentence 2. The user hears audio while the model is still thinking — this is what cuts ~73 ms from perceived latency.

    LLM:  [sentence 1]──────[sentence 2]──────[sentence 3]
TTS:       [gen audio 1]──────[gen audio 2]──────[gen audio 3]
User:           [hears audio 1]────[hears 2]────[hears 3]

    SNAC sliding-window decoding

    Each streaming chunk is decoded with one frame of left context from the previous chunk. This eliminates the waveform discontinuities at chunk boundaries that produce audible clicks in naive streaming.

    Chunk N:   [context_frame | new_frames...] → decode → trim context → output
Chunk N+1: [last_frame_N  | new_frames...] → decode → trim context → output

    Smart speech-end detection

    Orpheus uses EOS token 128258, which llama.cpp doesn't recognize as a stop. The trimmer uses multi-stage energy envelope analysis on 25 ms RMS windows to find where actual speech ends:

    1. Determine speech energy level from the core speech region
    2. Find sustained speech regions vs gaps
    3. Detect babble onset after a long gap (250 ms+)
    4. Duration-based fallback using word-count estimation
    5. Apply a 200 ms cosine natural release fade-out

    Stateful audio post-processing

    Pedalboard's streaming chain preserves compressor gain reduction and filter memory between chunks via reset=False. The result: streaming audio gets the same quality treatment as one-shot processing, with only ~0.04 UTMOS difference.

    Studio chain:    HPF → de-ess → 1.5:1 comp → warmth → clarity → air → limiter
Streaming chain: HPF → de-ess → parallel comp (Mix) → warmth → clarity → air → limiter
                                ↑ state preserved between chunks

    Whisper hallucination mitigation

    Following arXiv 2501.11378 and 2502.12414:

    1. condition_on_previous_text=False — prevents cascading hallucination loops
    2. no_speech_threshold=0.4 — aggressive non-speech filtering
    3. log_prob_threshold=-0.7 — tight confidence filtering
    4. compression_ratio_threshold=2.0 — repetition detection
    5. Per-segment avg_logprob filtering
    6. Known-hallucination phrase blocklist

    VRAM Budget

    GPU Component VRAM
    GPU 0 STT (faster-whisper large-v3-turbo) ~3 GB
    GPU 1 LLM (Llama 3.2 3B Q4_K_M + KV cache) ~2 GB
    GPU 2 TTS (Orpheus 3B Q4_K_M + SNAC codec) ~2.5 GB
    Total ~7.5 GB across 3 GPUs

    Each A10G has 23 GB — comfortable headroom for KV-cache scaling and concurrent sessions.
